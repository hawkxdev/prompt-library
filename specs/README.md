# Requirements and active work

Shared product contracts are listed in the [documentation index](../docs/knowledge-index.md). Add new agreed requirements here for their actual task. This directory does not invent product work or duplicate an issue's execution status. Internal planning and review archives are not repository prerequisites.

## Library portability acceptance

The unfinished work is retained on its separate portability acceptance branch. The [transfer architecture](../docs/architecture/library-transfer.md) and [document format](../docs/data/library-document-format.md) define behavior; the [portability verification contract](../docs/testing/library-portability.md) defines automated and live acceptance criteria.

Host and guarded platform journey tests and a representative limit-document generator exist on `feature/library-portability-repo2`, separately from `main`. Complete current-revision verification, live macOS/physical iPhone/iPad-simulator acceptance, a sanitized result record and independent review remain required. A repository reorganization does not accept this work, integrate it into `main`, or authorize live testing, installation or distribution. Continue only under a current product assignment.

Repository-only contributors can read the requirements from these files. A task requiring real library data or owner-operated devices needs separately supplied inputs and permission; private handoffs and local tool configuration are not part of this repository's shared requirements.
